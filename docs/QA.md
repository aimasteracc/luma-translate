# 検証記録 — v0.2.0

実施日: 2026-11-03（Asia/Tokyo）。Chrome for Testing、隔離した一時プロファイル。

## 自動検証

`npm test`: 12 件。設定、キャッシュ条件、Unicode 分割、プロンプトの境界、
API 形式、401/402/429/500、空応答・打ち切り、キャンセルに加え、以下を確認。

- 依存順の起動・逆順の停止・二重登録の防止。
- 起動失敗時のサービスとイベント登録のロールバック。
- 用語フックの解除と API サービスの差し替え。

`npm run test:browser`: 21 シナリオ合格。配布 manifest を変更しない。ローカル API と
翻訳対象を異なるホストに置き、未許可のサイトで拒否される状態から開始する。
ブラウザ自身のサイト設定 API で許可を事前承認し、実際の設定・側欄ボタンから
`chrome.permissions.request()` を呼ぶ。ネイティブ許可ダイアログのクリックは
自動化していない。側欄 HTML は独立した拡張機能ページとして操作する。

確認するシナリオ:

- 設定 UI でキー保存・接続確認・キー削除。接続確認は毎回 API を呼ぶ。
- 390px の設定・側欄で横スクロールがない。
- 未許可サイトの拒否、対象ホストを示す許可カード、許可後の翻訳ボタン。
- 側欄を開いたまま第2サイトへ移動し、そのサイトの権限で翻訳できる。
- 全文翻訳後のリンク・コード・フォーム・表・リスト・クリック処理の保持。
- content script から API キーを取得できない。
- 対訳 / 訳文のみ、原文への復帰。
- 動的な追加・変更、二重訳文の防止。
- フォーカス移動後の選択保持、再翻訳時の新規リクエスト。
- 401 によるキュー停止と再試行、エラー本文の非漏洩。
- 中断後の遅延 DOM 書き込み防止、自動翻訳の再読み込み。
- 划詞プラグイン停止でイベントが消え、再開後のリクエストは一度だけ。
- renderer 停止で原文に戻り、page / dynamic が依存不足として停止する。
- 辞書プラグインの停止が実際の送信プロンプトに反映される。

公開ページの追加確認は `LUMA_LIVE_SMOKE=1 npm run test:browser`。
翻訳レスポンスはこの場合もローカル API のテストデータであり、自然な翻訳の
品質や DeepSeek の実応答速度を検証するものではない。
2026-11-03 に example.com と Chrome for Developers の activeTab 文書で、
権限付与・側欄からの翻訳・元の本文ノードの復元を確認し、追加2件も合格。
実施結果は [browser-report-0.2.0.json](browser-report-0.2.0.json) を参照。

## 未検証・制限

- 実際の DeepSeek API キーによる疎通、課金、翻訳品質・実運用の速度。
- ネイティブ側欄の開閉、Chrome 自身の許可ダイアログを含む全操作の自動化。
- Edge 実機、Safari、Firefox、モバイル。
- 任意サイトの完全なレイアウト保持、PDF / OCR / 字幕 / iframe / サイトの Shadow DOM。
- 日常利用のブラウザプロファイルへのインストールは行っていない。
